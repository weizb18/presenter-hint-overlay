# M0 验证窗口

这不是浮层。它不透明、不置顶、不穿透，那些是 M1 的事。这个窗口是一台测量仪器，只用来在动手写浮层之前回答四个问题。

## 要回答的四个问题

1. `/edit?rm=minimal` 加载出来是不是没有编辑器界面
2. 后台在文档里打字，这边是不是实时出现
3. 断网十五秒的时候，Google Docs 在演讲者屏幕上显示什么
4. 窗口不聚焦挂一小时，内容会不会变陈旧

前两个看一眼就知道。后两个需要你真的去断一次网、真的挂一小时，搜索查不到答案。

## 跑起来

```
cd ~/presenter-hint-overlay
npm install
npm start
```

把 Google Doc 链接粘进上方输入框，回车。也可以跳过输入框：

```
npm start -- --url='https://docs.google.com/document/d/<文档ID>/edit'
```

## 文档那一侧要先设好

在 Google Docs 里把这个文档设成**知道链接的人可查看**。窗口用的是一个从未登录过的会话，所以文档没开放访问的话它只会被弹到登录页，状态栏会直接告诉你这件事。

顺便把正文字号调大到二十磅以上，这样你能顺带看出在演讲距离下的可读性。

## 状态栏在告诉你什么

**实时通道**：这是最重要的一项。Google Docs 只有在实时协作真正跑起来的时候才会对 `/document/d/<id>/bind` 发起长轮询，窗口拦截了这个请求。显示「已建立」就说明协作者的编辑一定会到达，不需要靠肉眼猜。如果它一直是「未建立」，说明你加载的地址不对。

**网络**：每两秒探一次。做断网测试的时候盯着它，同时看下面文档区域出现了什么。

**已加载**：从加载完成到现在过了多久。挂机测试就看这个数字，一小时之后回来让后台再打一行字，看还进不进得来。

**节流**：默认保持 Electron 的原始行为，也就是节流开着，这样挂机测试量到的是真实情况。如果一小时之后确实卡住了，用下面这条再跑一次，看是不是节流导致的：

```
npm run start:nothrottle
```

## 链接形式的坑

程序会自动把你粘的任何 Google Docs 链接改写成 `/edit?rm=minimal`，因为实测下来这是唯一同时满足「没有编辑器界面」和「能收到实时编辑」的形式。你不需要自己拼。

有一种链接会被拦下来警告：`/document/d/e/<id>/pub` 这种「发布到网络」的形式。Google 对它缓存约五分钟，收不到实时编辑，用它跑 M0 会得到一个假的否定结论。

## 判据

窗口里没有菜单栏工具栏、后台打字这边实时跟着变、状态栏的实时通道显示已建立，这三条同时成立，M0 就算过了，可以开始做 M1 的浮层。

任何一条不成立，先别写浮层，回来重新看方案。

---

# M1 浮层

M0 已于 2026-09-05 通过，三条判据全部成立。M1 是真正的浮层。

```
npm run overlay -- --url='https://docs.google.com/document/d/<文档ID>/edit'
```

链接只需要给一次，之后它记在配置里，直接 `npm run overlay` 就行。

## 快捷键

窗口没有边框也没有关闭按钮，点击还是穿透的，所以快捷键是唯一的控制手段。全部用三个修饰键，尽量不跟别的应用抢。

| 快捷键 | 作用 |
|---|---|
| `Cmd+Alt+Shift+O` | 隐藏 / 呼出浮层 |
| `Cmd+Alt+Shift+↑` | 上滚 |
| `Cmd+Alt+Shift+↓` | 下滚 |
| `Cmd+Alt+Shift+←` | 左移 |
| `Cmd+Alt+Shift+→` | 右移 |
| `Cmd+Alt+Shift+M` | 进出定位模式 |
| `Cmd+Alt+Shift+T` | 切换字色 |
| `Cmd+Alt+Shift+Q` | 退出程序 |

想改的话，配置文件路径启动时会打印，在 `~/Library/Application Support/presenter-hint-overlay/overlay-config.json`。

已知问题：Electron 有一个长期未修的缺陷，全局快捷键在非 QWERTY 键盘布局下不触发。所以快捷键做成了可配置的。

## 三个状态

**穿透态**是默认，也是整场演讲里它待着的状态。<b>浮层对鼠标完全惰性</b>，不接收点击、不接收滚轮、不接收键盘焦点。光标停在浮层上照样能点到、选中、打字到下面那个窗口里去，就跟浮层不存在一样。滚动走快捷键。

**定位态**按 `Cmd+Alt+Shift+M` 进入，这是唯一一个浮层会接收鼠标的时刻，为的是能拖动它。浮层会出现一圈绿框，拖到想要的位置，再按一次或者点右上角的锁定退出。位置自动保存，下次启动沿用。

**隐藏态**和上面两个正交。

早先的版本会在光标移到浮层上时自动关掉穿透，好让触控板能滚它。这个设计对本产品是错的：它意味着光标只要碰到提示区域，你就点不到、也打不了字到下面的窗口。已经砍掉。滚动多按一个键，换浮层彻底不挡路。

## 要看的几件事

浮层应该盖在 Chrome 上面，包括 Chrome 全屏放映幻灯片的时候。

**最重要的一条**：光标移到浮层上，试着点击和选中下面那个窗口里的东西，应该完全不受影响，就像浮层不存在。然后在下面的窗口里打字、按方向键，也应该完全正常。任何一条不成立都是硬缺陷，立刻告诉我。

滚动只有快捷键一条路径，四个方向都有。注意是按一次滚一段，**按住不会连续滚**，这是 macOS 底层用 Carbon 热键实现的限制，不是 bug。

左右移动是给「文档页面比浮层宽」这种情况用的。如果你不想每次都横着找内容，更根本的办法是在文档的「文件 / 页面设置」里把页面宽度改窄，窄到跟浮层差不多，横向就不会被截断了。

## 调整浮层大小

`Cmd+Alt+Shift+M` 进定位模式，右下角有个绿色拖拽角，拖它改大小，旁边实时显示尺寸。拖框本身移动位置。点「锁定」或再按一次 M 退出，位置和尺寸都会存下来。

这里没走原生 resize。Electron 文档写明透明窗口不可调整大小，而且把 `resizable` 设成 true「可能让透明窗口在某些平台上直接失效」，所以那个拖拽角是直接改窗口 bounds 的。

## 透明：三种观感模式

Google Docs 的正文是画在 canvas 上的，而且白色是**画进像素里**的，不是背后某个 DOM 元素的背景色。实测九万个采样点全是不透明白。所以从外面设 background transparent 一点用都没有，得换招。

按 `Cmd+Alt+Shift+T` 在三种模式之间循环，当场看哪种顺眼，选择会自动存进配置。

**keyed，默认。** 用一个 SVG 滤镜把亮度映射成透明度：白色底变成完全透明直接消失，深色的字保留下来，抗锯齿的边缘拿到按比例的半透明，所以字边不会发毛。**效果是背景真的没了，只剩文字浮在你的屏幕上，而且文字是完全不透明的。**

文字颜色默认是 `source`，也就是保持文档里本来的颜色。字号、颜色、加粗全部在文档里设，跟排版的其他部分保持一致，还能给紧急提示单独标个红色。想统一强制成一个颜色就把 `appearance.textColor` 改成十六进制，比如 `'#ffffff'`。

**dim。** 退路。把画布整体反相让页面读起来是深色的，再降低不透明度。实测在透明窗口里确实能合成出真半透明。缺点是文字跟着一起变透明，背后有亮色内容时会透过字来。

**off。** 不动 Google 的渲染，就是原来那个白盒子。

在配置文件里可以调 `appearance.textColor` 和 `appearance.opacity`。keyed 模式下 opacity 默认 1，也就是文字全不透明。

注意背后是什么颜色决定了文字该用什么颜色。压在深色的 VS Code 上要浅色字，压在白色幻灯片上要深色字。这个只能你自己看着定。

## 文档那一侧的设置

字号和排版仍然只能在文档里设，因为正文是 canvas，注入 CSS 改不了字号行高。正文调到 20 到 28 磅，页面设置里把页面改小、页边距调小。

**底色不用管**，keyed 模式会把它整个抠掉，文档里保持白底反而最好，因为亮度反差最大，抠出来的字最干净。字色照常在文档里设，默认配置会原样保留。

## 明确没做的

不调用 `setContentProtection`。它在 macOS 15 以上对 ScreenCaptureKit 无效，在 macOS 26 上还可能让窗口对你自己也不可见。隐身靠的是在 Zoom 里只共享 Chrome 那一个窗口。
